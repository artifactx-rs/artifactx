# ADR-0032: A2UI console for repository operations

- Status: Accepted (independent review: two blockers fixed; concerns addressed)
- Date: 2026-11-15
- Target: v0.4 UI and console ([#62](https://github.com/artifactx-rs/artifactx/issues/62))

## Review notes

Independent security review (2026-11-15) found two blockers, both fixed:
the console search moved from `POST` to a safe `GET` so token/OIDC
deployments can use it, and sensitive static-path checks now normalize
percent-decoded path components (`//`, `/./`, `%2e`, case-insensitive) before
comparison. The review's status-label, search-metric, asset-header, and
OpenAPI concerns were also addressed. A follow-up review caught that live apt/yum
metadata sits behind `.states` symlinks (and unsigned apt publishes emit
`Release`, not `InRelease`); the overview now resolves the live links and accepts
both forms.

## Context

ArtifactX has a complete CLI and HTTP API but no browser surface. #62 asks for a
console that makes repository state and existing operations visible without
creating a second behavior model. The console must reuse the v0.2 API and must
not become a separate source of truth.

A2UI is a good fit because the server can describe the surface as JSON and the
client renders it with native components. CopilotKit and an LLM are explicitly
not part of this slice: there is no natural-language requirement, and adding a
model runtime would introduce credentials, latency, and a second decision path
for operations that already have deterministic API semantics. The "agent" is a
small Rust handler that maps repository state to A2UI messages.

The visual direction comes from a generated design concept (dark developer
console, cyan/lime ArtifactX palette). Figma was evaluated for design authoring:
the desktop MCP server is read-only, and the remote MCP server rejected dynamic
client registration (HTTP 403), so this slice does not depend on Figma for
correctness. A design image is the reference; Figma can be attached later when
a supported MCP client/seat is available.

## Decision

### First slice: read-only overview and package search

- Add a `crates/arx/ui/` Vite + React app that uses `@a2ui/react` with a custom
  React catalog built from the A2UI v1.0 Basic Catalog schemas. Text, Row,
  Column, Card, List, and Button are React primitives styled with shadcn-style
  CSS tokens; components without an override fall back to the Basic Catalog.
  The app is served by `arx serve` at `/ui`.
- Add two same-origin endpoints:
  - `GET /api/v1/ui/overview` returns A2UI messages for the repository summary
    and the first package page.
  - `GET /api/v1/ui/search?q=…` handles the search action and returns
    `/query` and `/packages` data-model updates.
- The surface is data-only and read-only. It shows repository identity, package
  count, apt component/yum repo counts, last publish time, and a searchable
  package list. No upload, delete, publish, cutover, or rollback action is
  exposed in this slice.
- The Rust side stays authoritative: counts and rows come from the existing
  `pool::search` path; the UI never scans the repository itself.

### Build and delivery

- The console is built with `npm --prefix ui run build` and embedded into the
  `arx` binary with `include_dir`, keeping the one-binary distribution promise.
- CI builds the UI before Cargo. A missing `crates/arx/ui/dist` fails the build with an
  instruction, rather than silently shipping an empty console.
- The console is additive: without a browser, the CLI and API are unchanged.

### Later slices (separate changes)

- Publish/cutover/rollback actions with explicit confirmation and preflight.
- Authentication for write actions; this slice is read-only and same-origin.

## Consequences

- The repository gains a Node build step for the UI. This is limited to the
  `crates/arx/ui/` package and does not add a runtime service or database.
- A2UI messages are generated by deterministic Rust code, not by a model. The
  protocol can later be driven by an agent without changing the renderer.
- Figma authoring is not a dependency. The generated design and A2UI surface are
  the source of truth for this slice; Figma MCP connectivity remains a tooling
  follow-up.

## Acceptance

- `arx serve` serves `/ui` and the embedded assets from the binary.
- The dashboard loads repository counts and packages; searching updates the
  package list through the A2UI action endpoint.
- `cargo fmt`, `cargo clippy --workspace --all-targets --all-features -D warnings`,
  `cargo test --workspace --all-features`, and the UI build pass.
- A browser check confirms the rendered surface and search interaction.
